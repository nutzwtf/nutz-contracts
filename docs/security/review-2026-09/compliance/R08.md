## R08 — `MAX_SWEEP_ETH` per call plus router `minOut`

> "Also: Bound: `MAX_SWEEP_ETH` per call plus router `minOut`; keeper key cannot post a root alone."
> — docs/spec/engineering-spec.md §6, "Threat: keeper key compromise"

> "Max ETH per Sweep: `MAX_SWEEP_ETH = 20 ether`. Anything above waits for the next Sweep. This is the blast-radius cap."
> — docs/spec/engineering-spec.md §2.3

> "3. `ethIn = min(address(this).balance, MAX_SWEEP_ETH)`; zero reverts `NothingToSweep`."
> — docs/spec/engineering-spec.md §2.2 step 3

**Verdict:** implemented · confidence: high

**What this demands of an implementation:** in one `sweep` call, the ETH that leaves the Converter (to Ops and to the Venue) is at most `MAX_SWEEP_ETH = 20 ether`; the remainder of the balance stays in the contract for a later call; and every Leg carries the Route's `minOut` to its Venue.

**Where enforcement lives:**

```solidity
// src/NutzConverter.sol:L84
uint256 public constant MAX_SWEEP_ETH = 20 ether;

// src/NutzConverter.sol:L327-L333
uint256 ethIn = address(this).balance;
if (ethIn > MAX_SWEEP_ETH) ethIn = MAX_SWEEP_ETH;
if (ethIn == 0) revert NothingToSweep();
uint256 opsAmt = _fundOps(ethIn);
uint256 usdgOut = _ethToUsdg(routes[1], ethIn - opsAmt);
```
- `ethIn` is clamped to the constant, then split: `opsAmt` (≤ `ethIn × 200 / 10000`, L436-L437) leaves at L439; `ethIn − opsAmt` is the Venue input. The Venue receives exactly that: v3 `{value: ethIn ? amountIn : 0}` (L613) and v4 `settle{value: order.amountIn}` (L688) with `order.amountIn = amountIn` (L643). Total ETH out ≤ `opsAmt + (ethIn − opsAmt) = ethIn ≤ MAX_SWEEP_ETH`.
- No other ETH exit exists in the contract: the value-carrying sites are L439, L613, L688 only (grep `{value` → 3 hits; `.call(` → 1 hit, L439; no `transfer(`, `send(`, `selfdestruct`, `delegatecall`).
- `minOut` on every Leg: v3 `amountOutMinimum: route.minOut` (L609) is passed to `exactInput`; v4 `order.minOut` (L643) is compared in the callback at L676 (`InsufficientOutput`), and the callback also rejects a partial fill at L675.

**Paths walked:**
- Balance ≤ 20 ether → the whole balance is converted; balance − ethIn = 0 remains. ✓
- Balance > 20 ether → exactly 20 ether is split between Ops and the Venue; the excess is untouched by this call (no code reads the balance again after L327). ✓
- The NUTZ→ETH Leg (L324, `_sellNutz` L415-L423) runs *before* the clamp and sells the entire NUTZ balance (L416). Its ETH proceeds land in `address(this).balance` and are then subject to the clamp at L328. The cap therefore bounds the ETH→USDG conversion, as the document says; the NUTZ sale itself is bounded only by its `minOut` (L609/L676). The document specifies "sell the whole NUTZ balance" (§2.2 step 2), so this matches the document; it is noted because §6's sentence reads as if `MAX_SWEEP_ETH` bounded every Leg. —
- `convertAcorn` converts USDG, not ETH; no ETH cap applies and the document sets none. —
- Stock Legs: each consumes `perStock` (L338) of USDG derived from `usdgOut`, itself derived from ≤ 20 ether, so they inherit the cap transitively. ✓

**Searched:**
- `MAX_SWEEP_ETH` in `src/` → 2 hits: L84 constant, L328 clamp. No path bypasses it (the only ETH-spending function is `sweep`).
- `address(this).balance` in `src/NutzConverter.sol` → 1 hit, L327.
- `{value` in `src/` (non-vendor) → 3 hits, all in the Converter: L439 Ops, L613 v3, L688 v4.
- `minOut` in `src/NutzConverter.sol` → struct field L54, L63; v3 L609; v4 L643, L676 (and the error at L180). Every Leg passes through `_runLeg` (L564-L572), which dispatches to one of the two, so no Leg runs without its `minOut`.
- Lower bound on `minOut` → none: a Keeper may pass `minOut = 0`. The document accepts this (the threat is a compromised Keeper; the bound is the cap plus, for ETH→USDG, R07's floor).

**How the verdict was reached:** the cap is one clamp on the only variable that feeds every ETH exit, and each exit sends exactly its share. `minOut` reaches each Venue on both paths. Not `stronger-than-spec`: nothing beyond the documented constant is enforced. The NUTZ-sale nuance is documented behaviour, not a gap.
