## R13 — 2-of-3 signing: two distinct Signers, EIP-712, one global nonce, bound to chain and contract

> "**Signers** (`Signers.sol`, shared with the Converter): three keys, any two approve every privileged action by signing **EIP-712** typed data (`name = contract name, version = "1"`) that carries **one global nonce**. Instant actions: `postRoot`, `voidRoot`, `setKeeper`, `setRateRange`. Timelocked (propose with 2-of-3, execute by anyone after 48h, cancel with 2-of-3, expires 7 days after ready): signer rotation, Draw contract replacement, exclusion append."
> — engineering-spec.md §3.2

> "`Signers` (§3.2), with the Converter's own EIP-712 domain (`name = "NutzConverter"`): `setKeeper`, `proposeSignerRotation` / `executeSignerRotation`, `cancel`."
> — engineering-spec.md §2.2

> "`setOpsCap(uint256 cap, sig1, sig2)` — instant 2-of-3 over `SetOpsCap(uint256 cap,uint256 nonce)` […] `disableLeg(uint8 stock, sig1, sig2)` — the Circuit breaker (§6), instant 2-of-3 over `DisableLeg(uint8 stock,uint256 nonce)` […] `proposeLegEnable(uint8 stock, sig1, sig2)` — 2-of-3 over `EnableLeg(uint8 stock,uint256 nonce)`"
> — engineering-spec.md §2.2

**Verdict:** implemented · confidence: high

**What this demands of an implementation:** every state change that is not Keeper-only, Converter-only, permissionless-by-design (claims, `fulfill`, `execute*`) or a callback must recover two ECDSA signatures over an EIP-712 digest; the two recovered addresses must be different and both must be in `signers[3]`; the struct must include the contract's single `nonce`, consumed on success; the digest's domain must include `chainId` and `verifyingContract` (and the per-contract `name`) so a signature pair cannot be replayed on the same contract, on the other contract, or on another chain.

**Where enforcement lives:**

```solidity
// Signers.sol:L121-L129
function _require2of3(bytes32 structHash, bytes calldata sig1, bytes calldata sig2) internal {
    bytes32 digest = _hashTypedDataV4(structHash);
    address a = ECDSA.recover(digest, sig1);
    address b = ECDSA.recover(digest, sig2);
    if (a == b) revert SameSigner();
    if (!_isSigner(a)) revert NotSigner(a);
    if (!_isSigner(b)) revert NotSigner(b);
    nonce++;
}
```
- Distinctness: `a == b` reverts at L125; both must satisfy `_isSigner` (L131-L133: equality with `signers[0..2]`). `signers` are non-zero and pairwise distinct from the constructor (L46-L47) and `_checkRotation` (L92-L94: `to != 0`, `to` not already a signer), so two distinct recovered addresses are two distinct keys.
- Recovery: `ECDSA.recover` (OZ 5.7.0, `lib/openzeppelin-contracts/contracts/utils/cryptography/ECDSA.sol:L124-L127`) reverts on any error via `_throwError` (L273-L282); `tryRecover` rejects lengths other than 65 (L65-L78), high-`s` values (L185-L187) and a zero recovered address (L190-L193). So a malformed signature cannot recover to `address(0)`, and the same key cannot present two malleated encodings of one signature to pass the `a == b` test — the low-`s` rule makes the encoding unique per (key, digest).
- Nonce: `nonce` is one storage word per contract (L39), included in every struct hash by the caller (Signers L60, L69, L86; Distributor L279, L312, L425, L495, L510; Converter L264, L275, L284) and incremented once per successful check (L128). Any two privileged actions on one contract therefore consume consecutive nonces, and a pair of signatures is valid for exactly one nonce value.
- Chain and contract binding: `_hashTypedDataV4` (EIP712.sol:L119-L121) hashes with `_domainSeparatorV4` (L92-L98), which uses the cached separator only while `address(this) == _cachedThis && block.chainid == _cachedChainId` and otherwise rebuilds `keccak256(abi.encode(TYPE_HASH, _hashedName, _hashedVersion, block.chainid, address(this)))` (L100-L102). `TYPE_HASH` (L41) is the standard `EIP712Domain(string name,string version,uint256 chainId,address verifyingContract)`. The Distributor's domain name is `"NutzDistributor"` (NutzDistributor.sol:L173), the Converter's `"NutzConverter"` (NutzConverter.sol:L210), both version `"1"` (Signers.sol:L44). A signature for one contract fails on the other on two counts (name, verifyingContract) and on any other chain on `chainId`.

**How the verdict was reached:** `implemented` rather than `partial` because every path that the spec calls privileged is walked and lands on one `_require2of3`, and the three properties in the requirement (two distinct signers, one global nonce, chain+contract binding) are each enforced by a line that was read, not by a name: distinctness at L125-L127, the nonce at L128 plus every struct hash, the domain in OZ `_buildDomainSeparator` L101. **Open questions:**
- The signed struct carries no expiry: a pair of signatures over nonce `n` remains valid until some other 2-of-3 action consumes `n`. The spec does not ask for an expiry, so this is not a divergence; noted because the "one global nonce" design makes an unsubmitted signed action live indefinitely on a quiet contract.
- Anyone holding two valid signatures may submit the transaction (no `msg.sender` check in `_require2of3`). The action executed is the one signed, so this is consistent with "execute by anyone" and does not weaken the 2-of-3.
