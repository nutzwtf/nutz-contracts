## R18 — Stock Token pause/blocklist must never brick claims (`stuck`) or sweeps (leg skipped)

> "Stock Tokens are pausable and blocklist-capable by the issuer (§2.5), so transfer failures must never brick claims (`stuck` path) or sweeps (leg skipped)."
> — engineering-spec.md §6, "Threat: router/token behavior"

> "Consequences: (a) every stock leg in `sweep` and every stock transfer in `claim`/`pushClaims` is isolated in try/catch; a paused or blocked leg never blocks the others; (b) unpaid stock amounts land in `stuck[account][token]` and are claimable later; (c) a paused token during `sweep` makes that leg's USDG go to the Distributor as Cash for that epoch (§2.2 step 6); the Converter never carries balances between sweeps."
> — engineering-spec.md §2.5

> "**Threat: issuer blocklist / pause on a Stock Token (incl. the Distributor address being blocked).** […] (b) `stuck` path keeps the other four tokens flowing; (c) **circuit breaker** — `Converter.legDisabled[stock]` (`disableLeg`: 2-of-3 signers, instant; […]) reroutes that stock's share of the Stash slice into USDG at the next sweep […]; the keeper alerts after 3 consecutive failed transfers of a leg and the signers flip the flag."
> — engineering-spec.md §6

> "Approvals are per-swap, exact amount, and zeroed after, even when the swap failed."
> — engineering-spec.md §2.3

**Verdict:** partial · confidence: high

**What this demands of an implementation:** for each of the four Stock Tokens (and USDG, §2.5 "treat it with the same isolation as the stocks"), every `transfer`, `transferFrom` and `approve` that the contracts issue must either be wrapped so that a revert or `false` return does not abort the surrounding claim or sweep, or must be unreachable when the token is refusing. Claims: the amount lands in `stuck`. Sweeps: the leg is skipped and its USDG becomes Cash.

**Where enforcement lives — claims (holds):**

```solidity
// NutzDistributor.sol:L469-L488
function _payout(address account, uint256[5] memory amounts) private {
    for (i < 5) { if (amount == 0) continue;
        if (!_tryTransfer(tokens(i), account, amount)) { stuckOf[account][i] += amount; emit Stuck(account, i, amount); } }
}
function _tryTransfer(IERC20 token, address to, uint256 amount) private returns (bool) {
    (bool ok, bytes memory ret) = address(token).call(abi.encodeCall(IERC20.transfer, (to, amount)));
    return ok && (ret.length == 0 || abi.decode(ret, (bool)));
}
```
- A revert (`ok == false`) or a `false` return goes to `stuck`; the loop continues to the next token. Reached by `claim` L350, `claimMany` L371, `pushClaims` L412 (holders) and L417 (the fee to `msg.sender`, so a blocked Keeper address does not revert the batch either).
- `claimStuck` L433-L439 uses `safeTransfer`, which reverts on refusal; the whole call reverts so the record survives (NatSpec L431-L432: "Reverts, keeping the record, if the token still refuses"). It is a per-token, per-account retry and blocks nothing else.

**Where enforcement lives — sweep swap legs (holds):**

- `_buyStock` NutzConverter.sol:L481-L490 → `_runLeg` L564-L572 → `_runV3` L590-L621: `try V3_ROUTER.exactInput{…}` L613-L618 catches every revert inside the router, including the Stock Token refusing to `transfer` to the Converter; on `catch` the leg reports `ok == false` and `sweep` L338-L340 / `convertAcorn` L536-L538 add `perStock` to Cash. `_runV4` L627-L650: `try V4_POOL_MANAGER.unlock` L644-L649 catches everything in the callback, including `safeTransfer` to the manager at L690 and `take` at L695. ✓
- Circuit breaker: `legDisabled[stock]` short-circuits at L483-L486 before any Venue call. ✓
- Approvals around a swap: L612 `forceApprove(V3_ROUTER, amountIn)` and L619 `forceApprove(V3_ROUTER, 0)` run whether or not the `try` succeeded; the token approved is `tokenIn`, which for the four stock legs is USDG (`_legTokens` L706) and for `NutzToEth` is NUTZ — never a Stock Token. ✓ (§2.3 "zeroed after, even when the swap failed" holds at L619.)

**Where enforcement is missing — the funding hand-off (the gap):**

```solidity
// NutzConverter.sol:L493-L509
function _fundEpoch(...) { _approveFunding(amounts, usdg, true); DISTRIBUTOR.notifyEpochFunding(epochId, amounts, acornUsdg); _approveFunding(amounts, usdg, false); }
function _approveFunding(...) { for (i < 4) if (amounts[i] > 0) tokens(i).forceApprove(address(DISTRIBUTOR), grant ? amounts[i] : 0); if (usdg > 0) T4.forceApprove(...); }
```
```solidity
// NutzDistributor.sol:L214-L218 (notifyEpochFunding), L245-L247 (notifyDrawFunding)
for (i < 4) if (amounts[i] > 0) tokens(i).safeTransferFrom(msg.sender, address(this), amounts[i]);
```
- `forceApprove` (OZ SafeERC20.sol:L106-L110) reverts `SafeERC20FailedOperation` if `approve` reverts twice; `safeTransferFrom` (L44-L48) reverts on a revert or `false`. Neither is inside a `try`. Both run only when `amounts[i] > 0`, i.e. only when that stock's swap leg succeeded in the same transaction.
- So the sweep is bricked exactly when a Stock Token lets the Venue pay the Converter but refuses the Converter → Distributor hop. The blocklist case the spec itself names — "incl. the Distributor address being blocked" (§6) — is that case: `transferFrom(Converter, Distributor)` reverts on the blocked recipient, `notifyEpochFunding` reverts, `sweep` reverts as a whole (the try/catch of the earlier legs does not help; the revert is after them). Every subsequent `sweep` reverts the same way, and so does `convertAcorn` (L542 → `notifyDrawFunding` L246), until the Signers `disableLeg(stock)` (2-of-3, instant, L272-L278), after which `amounts[stock] == 0` and the hop is skipped. The pause case is caught earlier by the swap leg (the Venue cannot deliver a paused token), unless the issuer's pause covers `approve` but not the pool's transfer, which cannot be determined from `src/`.
- Consequence while bricked: no Epoch is funded (the ETH stays in the Converter; NUTZ fees stay in the Pons escrow; nothing is lost), Holders receive nothing for those hours, and unblocking needs a governance action. That is "bricked until 2-of-3 act", not "never brick".

**How the verdict was reached:** `partial`, not `implemented`: the requirement names two paths, claims and sweeps, and the claim path is isolated on every transfer, while the sweep path is isolated on the swap legs and not on the funding hop — and the unisolated hop is reachable in the scenario the spec's own threat entry names (the Distributor address blocked). Not `contradicted`: the spec's §6 entry (c) describes the circuit breaker plus Keeper alerting as the response to exactly this, so the code follows the documented mitigation; what does not hold is the stronger sentence "transfer failures must never brick […] sweeps (leg skipped)" and §2.5 (a) "every stock leg in `sweep` […] is isolated". The fix direction is a documentation choice (say "until `disableLeg`") or a code choice (isolate the funding hop per token, e.g. a `try` around the Distributor call with the refused stock's share falling back to Cash); recording the divergence, not choosing.

**Open questions:**
- `_tryTransfer` L487: `abi.decode(ret, (bool))` reverts if `ret` is not exactly a clean 32-byte boolean. A Stock Token upgrade that returned malformed data would make every claim carrying that token revert instead of going to `stuck`. Unreachable for the §2.5 "Standard ERC-20" tokens; recorded because the tokens are upgradeable by the issuer.
- Whether Robinhood's pause covers `approve` (which would make L506 reachable under a pause) cannot be established from `src/`; §9 Q2's residual ("behavior while paused, and whether contracts can be blocklisted") is the fork test that would settle it.
