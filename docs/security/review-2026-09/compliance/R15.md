## R15 — the Seed: quicknet signature for the committed round, verified on-chain; round strictly future and strictly increasing; fulfilment final

> "We therefore commit each Acorn Draw to a drand quicknet round ten minutes in the future, together with the Ticket list's root, and let anyone submit that round's signature; the Draw contract verifies it against the hard-coded quicknet public key and stores `sha256(signature)`, which is the `randomness` value drand itself publishes, as the Seed."
> — docs/adr/0004-drand-quicknet-verified-on-chain.md

> "A wrong Ticket list can be re-committed until the draw is fulfilled; after that the Seed is final and only the 2-of-3 Root decides what is paid."
> — docs/adr/0004-drand-quicknet-verified-on-chain.md, Consequences

> "`requestDraw(drawId, ticketsRoot, ticketCount)` — Keeper. Requires `drawId < currentDraw()`, not yet fulfilled, and `ticketsRoot != 0 && ticketCount > 0` […] Commits the Ticket list […] **and** the target round `R = max(roundAt(block.timestamp + 10 min), lastRound + 1)`, `roundAt(t) = (t − genesis) / 3 + 1` — both before the beacon value exists, so nobody can choose the Ticket list with knowledge of the Seed. Rounds are strictly increasing across every request, so two Acorn Draws never share a Seed. An unfulfilled Acorn Draw may be requested again […]"
> — engineering-spec.md §3.4

> "`fulfill(drawId, bytes signature)` — **permissionless**. Takes the 48-byte compressed G1 signature, decompresses it on-chain and verifies `BLS.verify(PK_quicknet, H(sha256(R)), signature)` through the precompiles; stores `seed = sha256(signature)` […] Reverts `RoundNotDue` if `currentRound() < R` and `InvalidSignature` on anything else (wrong length, flag bits, point, or round). Once fulfilled the Seed is final: no re-request, no second fulfilment."
> — engineering-spec.md §3.4

**Verdict:** implemented · confidence: high

**What this demands of an implementation:** (1) at request, the stored round is greater than the round covering `block.timestamp` and greater than every previously stored round; (2) at fulfilment, the stored seed is `sha256(sig)` only if `sig` is a valid BLS12-381 G1 signature over drand's message for that exact round under the quicknet G2 key, checked by an on-chain pairing; (3) once `seed != 0`, neither `requestDraw` nor `fulfill` can change it.

**Where enforcement lives:**

```solidity
// NutzDraw.sol:L105-L124 (request)
if (msg.sender != DISTRIBUTOR.keeper()) revert NotKeeper();
if (drawId >= DISTRIBUTOR.currentDraw()) revert DrawNotOpen(drawId);
Draw storage d = draws[drawId];
if (d.seed != 0) revert AlreadyFulfilled(drawId);
if (ticketsRoot == 0 || ticketCount == 0) revert NoTickets();
uint64 round = roundAt(block.timestamp + LEAD);     // LEAD = 10 minutes, L37
uint64 next = lastRound + 1;
if (next > round) round = next;
lastRound = round;
d.ticketsRoot = ticketsRoot; d.ticketCount = ticketCount; d.round = round;
```
- Strictly future: `roundAt(t) = (t − GENESIS) / PERIOD + 1` (L162-L164), `PERIOD = 3` (L34). With `LEAD = 600 = 200 × PERIOD`, `roundAt(now + 600) = roundAt(now) + 200` exactly (600 is a multiple of 3, so the floor division adds exactly 200). drand publishes round `R` at `GENESIS + (R−1)·3`, so the committed round is published no earlier than `now + 600 − 2` seconds. The `max` with `lastRound + 1` can only push it further out. ✓
- Strictly increasing: `lastRound` is written on every request (L119) to a value ≥ `lastRound + 1` (L117-L118); a re-request of an unfulfilled draw goes through the same lines, so it also moves strictly up. ✓
- Re-request blocked once fulfilled: L112. ✓

```solidity
// NutzDraw.sol:L133-L146 (fulfil)
uint64 round = d.round;
if (round == 0) revert DrawNotRequested(drawId);
if (d.seed != 0) revert AlreadyFulfilled(drawId);
uint64 current = currentRound();
if (current < round) revert RoundNotDue(round, current);
if (signature.length != SIGNATURE_BYTES || !_wellFormed(signature) || !_verify(round, signature)) revert InvalidSignature();
bytes32 seed = sha256(signature);
d.seed = seed;
```
- Second fulfilment blocked: L137. Length 48: L140 (`SIGNATURE_BYTES = 48`, L47). Flags: `_wellFormed` L170-L173 (compressed bit set, infinity bit clear).
- The verification, `_verify` L179-L184: `BLS2.g1UnmarshalCompressed(signature)` (BLS2.sol:L71 — decompresses; the flag checks it would `require` on are pre-screened by `_wellFormed`); `message = hashToPoint(DST, sha256(abi.encodePacked(round)))` — `abi.encodePacked(uint64)` is the 8-byte big-endian round, `sha256` of it is drand's unchained message, `DST` (L39) is the RFC 9380 tag of `bls-unchained-g1-rfc9380`; then `BLS2.verifySingle(sig, _publicKey(), message)` (BLS2.sol:L339-L375) builds the 2-pair input `(sig, −G2gen), (message, PK)` and `staticcall`s the EIP-2537 pairing precompile at `0x0f` (Precompiles.sol:L23, BLS2.sol:L372). `_verify` returns `ok && callOk` (L183): a point the precompile rejects (off curve, wrong subgroup) makes `callOk` false, a wrong signature or wrong round makes `ok` false; either way `fulfill` reverts `InvalidSignature` and nothing is stored. ✓
- Against the quicknet key: `_publicKey()` L190-L201 is a hard-coded G2 point; the constructor (L92-L97) runs `_verify(VECTOR_ROUND, VECTOR_SIG)` (L41-L44, round 1000) and reverts `VerifierSelfTestFailed` on failure, so the deployed key and the vendored verifier are consistent with a recorded quicknet signature.
- Seed: `sha256(signature)` L143, stored L144; read by the Distributor through `seedOf` L151-L153. ✓

**Paths walked:**
- `requestDraw` fresh draw → all checks → `lastRound` and `draws[id]` written. ✓
- `requestDraw` re-request before fulfilment → same path; root, count, round replaced, round strictly above `lastRound`. ✓ (spec'd)
- `requestDraw` after fulfilment → `AlreadyFulfilled` L112 before any write. ✓
- `requestDraw` by non-Keeper → L108; for the current or a future week → L110. ✓
- `fulfill` never requested → L136; already fulfilled → L137; round not yet published → L139; bad length / flags / pairing → L140-L141. Only the surviving path writes `d.seed`. ✓
- `_verify` internal branches: `g1UnmarshalCompressed` `require`s on length and flags (BLS2 L72, L91-L96) are unreachable from `fulfill` because L140 screens them first; the constructor self-test passes a 48-byte flagged vector (L43-L44).
- Who reads the seed: Distributor `_requireFulfilled` L250-L254 → `seedOf(drawId) == 0` reverts `DrawNotFulfilled`; callers `pullAcorn` L224 and `postRoot(Kind.Draw)` L276 (R16).

**Searched:**
- Writes to `draws[` / `d.seed` / `d.round` / `lastRound` in `src/` → L119-L122 (request), L144 (fulfil). No other write; no setter, no owner, no upgrade path in `NutzDraw` (no `selfdestruct|delegatecall|owner|upgrade` hits in the file).
- `LEAD|roundAt|currentRound|GENESIS|PERIOD` → declared L32-L37, used at L116, L138, L157, L163. Constants match §3.4 (`genesis 1692803367`, 3 s, 10 min).
- `DST` → L39, used L181. String equals the spec's scheme tag suffix for G1 `SSWU_RO` with `NUL_` (drand unchained-g1 DST).
- `BLS12_PAIRING_CHECK` → `0x0f` at Precompiles.sol:L23, called at BLS2.sol:L372 with 768 bytes = 2 pairs × (128 G1 + 256 G2). Input layout at BLS2.sol:L344-L369 places the signature with the negated G2 generator (`N_G2_*`) and the message with `pubkey`.
- `seedOf` → interface `INutzDraw.sol:L8`, implementation L151, consumer Distributor L253.

**How the verdict was reached:** `implemented` because each of the three properties is a read line: the round arithmetic (L116-L119, L162-L164), the pairing call chain down to the precompile address, and the two `AlreadyFulfilled` guards. It is not `partial`: there is no branch in `requestDraw` or `fulfill` that writes without passing the checks. The self-test at construction ties the hard-coded key to a real quicknet signature, which is the strongest in-repo evidence that "the quicknet public key" is what is hard-coded; the remaining gap is procedural (below).

**Open questions:**
- Whether the limbs at L192-L199 equal quicknet's published key cannot be established from `src/` alone; the constructor self-test proves (key, VECTOR_SIG) are a consistent pair for round 1000, and §10 step 2 assigns the comparison with `/info` to a human before deploy. `test/unit/BlsVerifier.t.sol` re-derives the compressed form (in tests, not enforcement).
- `RoundNotDue` compares against `roundAt(block.timestamp)`; a sequencer timestamp skewed a few seconds early could reject a just-published round until the next block. No security consequence (the Seed is fixed by the round, not by when it is submitted).
