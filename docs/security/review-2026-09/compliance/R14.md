## R14 — the 48-hour timelock: schedule, execute-by-anyone inside the window, re-check, cancel

> "Timelocked (propose with 2-of-3, execute by anyone after 48h, cancel with 2-of-3, expires 7 days after ready): signer rotation, Draw contract replacement, exclusion append."
> — engineering-spec.md §3.2

> "`proposeLegEnable(uint8 stock, sig1, sig2)` — 2-of-3 over `EnableLeg(uint8 stock,uint256 nonce)`, scheduled through the shared 48h timelock; `executeLegEnable(uint8 stock)` by anyone once ready (7-day TTL, cancellable with `Signers.cancel`)."
> — engineering-spec.md §2.2

> "`NutzDraw` holds no funds and has no governance; the Distributor names it through `proposeDrawContract` / `executeDrawContract` (2-of-3, 48h timelock, disclosed)"
> — engineering-spec.md §3.4

> "The exclusion list lives **in the Distributor** (`excluded()`): base list at deploy, appended through `proposeExclusion` / `executeExclusion` (2-of-3, 48h timelock) […] Never removable."
> — engineering-spec.md §3.5

**Verdict:** implemented · confidence: high

**What this demands of an implementation:** four scheduled actions (rotation, draw contract, exclusion, leg enable). Each `propose*` needs 2-of-3 (R13) and records `readyAt = now + 48h`; each `execute*` has no access restriction, reverts before `readyAt` and after `readyAt + 7 days`, re-validates the action's preconditions at execution time, and consumes the schedule so it runs once; `cancel` needs 2-of-3 and clears the schedule.

**Where enforcement lives:**

```solidity
// Signers.sol:L98-L117
function _schedule(bytes32 id) internal {
    if (readyAt[id] != 0) revert AlreadyScheduled();
    uint256 ready = block.timestamp + TIMELOCK;      // TIMELOCK = 48 hours, L30
    readyAt[id] = ready;
    emit Scheduled(id, ready);
}
function _consume(bytes32 id) internal {
    uint256 ready = readyAt[id];
    if (ready == 0) revert NotScheduled();
    if (block.timestamp < ready) revert NotReady();
    if (block.timestamp > ready + PROPOSAL_TTL) revert Expired();   // PROPOSAL_TTL = 7 days, L32
    delete readyAt[id];
    emit Executed(id);
}
```
- The delay is the constant `TIMELOCK = 48 hours` (L30); the window is `[ready, ready + 7 days]` inclusive (L112, L114); `delete` at L115 makes execution single-shot.
- The schedule id is `keccak256(abi.encode(TYPEHASH, args))` without the nonce (Signers L70, Distributor L496/L511, Converter L285), so the same action cannot be double-scheduled (`AlreadyScheduled`, L99) and `execute*` recomputes the same id from its arguments.

```solidity
// Signers.sol:L83-L89
function cancel(bytes32 id, bytes calldata sig1, bytes calldata sig2) external {
    if (readyAt[id] == 0) revert NotScheduled();
    _require2of3(keccak256(abi.encode(CANCEL_TYPEHASH, id, nonce)), sig1, sig2);
    delete readyAt[id];
    emit Cancelled(id);
}
```
- `cancel` is inherited by both contracts, so it covers all four action types (the Converter's `EnableLeg` id included).

**How the verdict was reached:** `implemented` because all four scheduled actions go through the same two internal functions, each of which was read, and every `execute*` re-runs the same precondition helper the `propose*` ran (or, for the draw contract, the only precondition that exists). Not `stronger-than-spec`: the 7-day TTL and the re-check are both stated in the spec.

**Open questions:**
- `executeDrawContract` accepts any non-zero address with no code check; a wrong address would make `_requireFulfilled` (Distributor L253) revert on the `seedOf` call until replaced by another 48h cycle. The spec asks for nothing more than the timelock here, so not a divergence.
- After a Draw contract replacement, `drawConverted[id]` for a draw converted under the old contract stays `true`, but `seedOf(id)` on the new contract is zero, so that draw's Root can never be posted and its funding is Skipped into `drawCarry` by the next Draw Root (Distributor L284-L286, L325-L339). Consistent with ADR-0004 ("the weeks in between are Skipped and their pool rolls forward"); recorded under R16 as well.
