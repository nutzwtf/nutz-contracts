## R11 — No fee-recipient transfer; no exit but the Sweep's own paths

> "Controls: the Converter has no transfer function, so the instant path is closed; the keeper pages on the proposal event and the pending getter, and we announce within the 3 days; balances already credited to the escrow remain claimable by the Converter."
> — docs/spec/engineering-spec.md §6, "Threat: Pons redirects the creator fee recipient"

> "**No fee-recipient transfer, no buyback switch.** The Converter exposes no path to `factory.transferCreatorFeeRecipient` or `factory.setBuybackEnabled`. As the recipient it is the only address that could call them, so the absence of the function is the guarantee"
> — docs/spec/engineering-spec.md §2.2

> "(a) `factory.transferCreatorFeeRecipient(token, new)` by the current recipient, immediate: closed for us because the Converter has no such function."
> — docs/spec/engineering-spec.md §2.4

**Verdict:** implemented · confidence: high

**What this demands of an implementation:** no function in `NutzConverter` (including inherited `Signers`) can cause a call to `PONS_FACTORY.transferCreatorFeeRecipient` or `setBuybackEnabled`, whether by name, by a generic low-level call with caller-chosen target or calldata, or by `delegatecall`; and every way ETH or tokens leave the contract is one of the Sweep's / Acorn conversion's fixed paths to fixed counterparties.

**Where enforcement lives:** an absence, established by enumerating the whole contract. The complete list of external calls and value transfers `NutzConverter` makes (every `.` call on an external address in `src/NutzConverter.sol`, checked line by line against the full file, L1-L726):

**Paths walked:**
- `sweep` → `_pullFees` → L366/L387/L405: Pons calls that only move value *toward* the Converter. ✓
- `sweep` → `_fundOps` → L439: ETH out to `keeper`, bounded (R08 record). The destination is changed only by `setKeeper` under 2-of-3. ✓
- `sweep`/`convertAcorn` → Venue calls: ETH/ERC-20 out only as swap input to the two immutable Venues, with the output returned to `address(this)` (`recipient: address(this)` L609; `take(cout, address(this), …)` L695). ✓

**How the verdict was reached:** this is an absence claim and it is earned by enumeration rather than search alone: every external call in the 726-line file was listed with its target and what it moves, and none is a generic or caller-directed call. The two named factory functions are not declared in any interface the contract imports, so even a future edit would have to add both the declaration and a call site. Confidence is high.
