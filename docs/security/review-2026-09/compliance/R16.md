## R16 — no Draw contract ⇒ `pullAcorn` and Draw Roots revert `NoDrawContract`, the pool accumulates; a Draw Root and `pullAcorn` need a reported Seed and one conversion per draw

> "*Scope rule.* `NutzDistributor` + `Signers` and `NutzConverter` launch first. `NutzDraw` is deployed after launch, wired through the 48h `proposeDrawContract` / `executeDrawContract` timelock, once item 10 is green; until then `pullAcorn` and Draw Roots revert `NoDrawContract` and the Acorn pool accumulates in the Distributor (§10 step 8)."
> — engineering-spec.md §6

> "Once the Draw is deployed: the Signers `proposeDrawContract(draw, sig1, sig2)` […]; 48 hours later anyone `executeDrawContract(draw)`. `pullAcorn` and Draw Roots revert `NoDrawContract` until then."
> — engineering-spec.md §10 step 2

> "`pullAcorn(drawId)` — `onlyConverter`, once per draw, only when the Draw contract reports a seed: transfers the whole `acornPoolUsdg` to the Converter. `notifyDrawFunding(drawId, amounts[5])` — `onlyConverter`, requires conversion; USDG from a failed leg lands in `funded[USDG]`."
> — engineering-spec.md §3.3

> "For `Kind.Draw` additionally requires `drawConverted[id]` and a seed from the Draw contract."
> — engineering-spec.md §3.3 (`postRoot`)

> "`convertAcorn(uint256 drawId, Route[4] routes, uint256 deadline)` — `onlyKeeper`, `nonReentrant`. `DISTRIBUTOR.pullAcorn(drawId)` (the Distributor enforces once per Draw, seed reported, pool non-empty; §3.4)"
> — engineering-spec.md §2.2

> "The Distributor refuses to release the Acorn pool or accept a Draw Root without a Seed"
> — docs/adr/0004-drand-quicknet-verified-on-chain.md

**Verdict:** implemented · confidence: high — with one documentation drift on the error selector for Draw Roots (below).

**What this demands of an implementation:** with `drawContract == 0`: `pullAcorn` reverts, `postRoot(Kind.Draw, …)` reverts, and `notifyEpochFunding` keeps adding `acornUsdg` to `acornPoolUsdg` with no other drain. With a Draw contract set: `pullAcorn(id)` requires `seedOf(id) != 0`, runs at most once per `id`, and empties the pool; `postRoot(Kind.Draw, id)` requires `drawConverted[id]` and `seedOf(id) != 0`.

**Where enforcement lives:**

```solidity
// NutzDistributor.sol:L250-L254
function _requireFulfilled(uint256 drawId) private view {
    INutzDraw draw = drawContract;
    if (address(draw) == address(0)) revert NoDrawContract();
    if (draw.seedOf(drawId) == bytes32(0)) revert DrawNotFulfilled(drawId);
}
```
```solidity
// NutzDistributor.sol:L223-L234 (pullAcorn)
_requireFulfilled(drawId);
if (drawId > currentDraw()) revert PeriodNotOpen(drawId);
if (drawId <= drawBook.rootedThrough) revert PeriodClosed(drawId);
if (drawConverted[drawId]) revert AlreadyConverted(drawId);
uint256 usdg = acornPoolUsdg;
if (usdg == 0) revert NothingToConvert();
drawConverted[drawId] = true;
acornPoolUsdg = 0;
emit AcornPulled(drawId, usdg);
T4.safeTransfer(msg.sender, usdg);
```
```solidity
// NutzDistributor.sol:L274-L277 (postRoot, Draw branch)
if (kind == Kind.Draw) {
    if (!drawConverted[id]) revert NotConverted(id);
    _requireFulfilled(id);
}
```
- `pullAcorn`: first statement is `_requireFulfilled` → `NoDrawContract` when unset, `DrawNotFulfilled` when the Seed is zero; once-per-draw at L227/L230; pool emptied at L231; `onlyConverter` at L223. ✓
- `postRoot(Draw)`: `drawConverted` at L275 and the Seed at L276, before the 2-of-3 at L278. ✓
- `notifyDrawFunding` L237-L248: `drawConverted` at L238 (spec: "requires conversion"). ✓
- Accumulation: `acornPoolUsdg += acornUsdg` at L212 is unconditional on the Draw contract; the only decrement is L231 inside `pullAcorn`. ✓

**Paths walked:**
- No Draw contract, `pullAcorn` → `NoDrawContract` at L252 (first check). ✓ matches the spec's selector.
- No Draw contract, `postRoot(Kind.Draw, id)` → L272-L273 period checks, then L275 `!drawConverted[id]` → `NotConverted(id)`. `drawConverted[id]` can only become `true` at L230, which is reachable only after `_requireFulfilled` at L224 passed, i.e. only with a Draw contract set. So with no Draw contract ever set, a Draw Root always reverts `NotConverted`, never reaching L276. It reverts, as required; the selector is not the one the spec names (drift, below). `test/unit/DistributorDraw.t.sol:L228` expects `NotConverted` for this case (in tests).
- Draw contract set, Seed absent: `pullAcorn` → `DrawNotFulfilled` L253; `postRoot(Draw)` after conversion → `DrawNotFulfilled` L253 (conversion itself needed the Seed, so this branch is reachable only if the Draw contract was replaced in between; see open questions).
- Draw contract set, Seed present, second `pullAcorn(id)` → `AlreadyConverted` L227. Empty pool → `NothingToConvert` L229. ✓
- Draw contract set, `postRoot(Draw, id)` with `drawConverted[id]` and Seed → passes to the 2-of-3 and cap checks (L278-L295). ✓
- `notifyDrawFunding` without conversion → `NotConverted` L238. With conversion: no once-only guard (the Converter may call it more than once for one draw; `funded` accumulates, L241-L243). The spec says "requires conversion", not "once", and the only caller `convertAcorn` (NutzConverter.sol:L522-L544) calls `pullAcorn` first (L530), which is once-only, and then `_fundDraw` once (L542, L547-L551). Not a divergence.
- Other drains of `acornPoolUsdg` → none (search below), so the pool accumulates across every hour the Draw is unwired.

**Searched:**
- `acornPoolUsdg` in `src/` → L91 declaration, L212 `+=`, L228 read, L231 `= 0`. No other write.
- `drawConverted` → L92 declaration, L227 read, L230 write, L238 read, L275 read. Single write site, behind `_requireFulfilled`.
- `_requireFulfilled(` → definition L250, calls L224 (`pullAcorn`), L276 (`postRoot` Draw branch). No third path releases the pool or posts a Draw Root.
- `NoDrawContract` → error L125, raised L252 only. `DrawNotFulfilled` → L127, raised L253 only. `seedOf` → `INutzDraw.sol:L8`, `NutzDraw.sol:L151`, consumer L253.
- `drawContract` writes → L503 (`executeDrawContract`, behind the timelock, R14) only; initial value zero (no constructor assignment, L163-L195).
- `Kind.Draw` in `postRoot` → L274 only; the Epoch branch has no Draw checks, as intended.
- Tests (not enforcement): `NoDrawContract` expected in 3 test files; `test/unit/DistributorDraw.t.sol:L100` (pullAcorn) and `L228` (postRoot → `NotConverted`).

**How the verdict was reached:** `implemented` because every behavioural clause holds on a read line: both release paths sit behind `_requireFulfilled`, the once-per-draw flag has one write site behind it, and the pool has one drain. The one mismatch is which error a Draw Root raises when no Draw contract exists (`NotConverted` in code, `NoDrawContract` in §6 and §10): the transaction reverts either way and no state moves, so under the rubric this is documentation drift (the Keeper decodes errors, §2.2, so the spec line should name `NotConverted(id)` for Draw Roots, or the two checks at L275-L276 should be swapped). Not `partial`: no path releases the pool or accepts a Draw Root without a Seed.

**Open questions:**
- After `executeDrawContract` replaces the Draw, a draw converted under the old contract (`drawConverted[id] == true`, pool already pulled and funded) has `seedOf(id) == 0` on the new one, so its Root reverts `DrawNotFulfilled` forever and the next Draw Root Skips it into `drawCarry` (L284-L286, L325-L339). Funds stay in the Distributor and reach the next Draw; consistent with ADR-0004's "weeks in between are Skipped". The spec does not say what happens to an already-converted-but-unrooted draw at replacement; worth one sentence in §3.4.
